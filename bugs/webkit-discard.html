WebGPU in WebKit: two discards in one fragment shader put garbage in the colour attachment

This page does not yet reproduce the fault. It is the record of a search: every configuration below passes, in both Safari and Chrome. It is here so that whoever picks the bug up does not repeat the same ground.

The fault is real and reproduces reliably in a full renderer (webgpu-aquarium). There, a fragment shader writes a constant and the colour attachment still comes back with NaN texels — inside the drawn object, interleaved with texels holding the constant. A discarded fragment must not write at all, so the value landing in the target is not something the shader computed.

What was established there, by toggling one thing at a time:

  • Two discard statements in the one fragment shader are required. With either one alone the frame is clean; with both, roughly 2,600 NaN texels appear over 12 seconds. This is presumably why ordinary alpha-tested transparency, which discards once, is unaffected.
  • The rest of the shading has to be live. Cut the shader down to the discards and a constant — so the compiler eliminates everything else — and it is clean.
  • It is not the arithmetic: with the outputs forced to a constant, every derivative removed, and the outputs initialised before the discards, the NaNs still appear.
  • Chrome is clean throughout on the same hardware.

Each variant below draws a triangle whose fragment shader writes one constant colour and discards a pseudo-random share of its pixels, over 120 frames reusing one set of textures. Every texel must end up either the clear value or that exact constant; anything else is counted. Ruled out as sufficient: one or two colour attachments, rgba16float and rgba8unorm, a depth attachment with reversed-Z, 200 overlapping instances, drawIndirect and drawIndexedIndirect, a discard pattern reseeded every frame, flat varyings and front_facing, a storage-buffer read in the fragment, implicit- and explicit-LOD texture sampling, two discards, and heavy live arithmetic between them.

Magenta marks a NaN texel, red any other unexpected value, grey the written constant, black the clear value.
